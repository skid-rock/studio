# Дорожная карта: документация сервиса и архитектуры

Документы, которые стоит завести — чтобы (1) владелец быстрее погружался в сервис
и (2) у ИИ был контекст, снижающий неверные предложения (прямая связь с
[roadmap-control.md](roadmap-control.md)). Сами документы пишутся позже, по
очереди; здесь — план, приоритеты и триггеры.

## Принцип организации

Документация делится по типам (подход Diátaxis); слой «решения» уже закрыт ADR:

| Тип                | Отвечает на         | Где                             |
| ------------------ | ------------------- | ------------------------------- |
| Объяснение / карта | почему так устроено | `docs/architecture.md` (D1)     |
| Справочник         | как устроено точно  | `docs/reference/*` (D4, D6)     |
| Гайд / how-to      | как сделать         | `docs/guides/*` (D5)            |
| Словарь            | что значит термин   | `docs/glossary.md` (D2)         |
| Решения            | почему так решили   | [docs/adr/](../adr/) — уже есть |
| Контекст для ИИ    | правила и границы   | `CLAUDE.md` (D3)                |

Польза каждого пункта помечена: **тебе** (онбординг) / **ИИ** (контекст) / **обоим**.

## D1. Обзор архитектуры (keystone)

> ✅ Сделано в STUDIO-028 — [`docs/architecture.md`](../architecture.md).

- **Артефакт:** `docs/architecture.md`.
- **Зачем:** знание о структуре размазано по четырём ADR. Нужна одна живая карта —
  якорь и для онбординга, и для ИИ.
- **Содержит:** гексагон и слои (`render-core`/`sections`/`tokens`/`editor`);
  правило зависимостей «внутрь» (явно: ядро не знает про React/движок — связь с
  R1); поток данных `StudioDocument → renderDocument → HTML/CSS`; где изолирован
  движок. Сводит ADR-0001/0002/0004 в одно место (ADR остаются как «почему»).
- **Польза:** оба. **Приоритет:** высокий — делать первым.

## D2. Глоссарий / единый язык

> ✅ Сделано в STUDIO-029 — [`docs/glossary.md`](../glossary.md).

- **Артефакт:** `docs/glossary.md`.
- **Зачем:** единый язык (ubiquitous language) — опора владельцу при погружении,
  а ИИ перестаёт путать термины.
- **Содержит:** `StudioDocument`, `SectionNode`, `BlockModule`, `ParamSchema`,
  `registry`, `render-core`, дробный `order` (fractional index), `theme`/токены,
  drift/anti-drift, full-bleed, гранулярность inline, preset — короткое
  определение + где в коде.
- **Польза:** оба. **Приоритет:** высокий.

## D3. Проектный `CLAUDE.md` (контекст для ИИ)

> ✅ Сделано в STUDIO-028 — [`CLAUDE.md`](../../CLAUDE.md) в корне проекта.

- **Артефакт:** `CLAUDE.md` в корне проекта.
- **Зачем:** самый прямой ответ на «польза для нейронки» — гасит неверные
  предложения у источника. Дополняет глобальный `~/.claude/CLAUDE.md` (не дублирует
  стиль/правила общения, а добавляет проектную специфику).
- **Содержит:** правило границ (`render-core`/`sections` ↛ React/движок); карту
  «где что лежит»; ключевые инварианты (источник правды — `StudioDocument`; render —
  чистая строка; экспорт без React); конвенции (комментарии на русском; решения —
  через ADR; техдолг — в [backlog.md](backlog.md)); ссылки на D1/D2. Завязан на R1/R2.
- **Процесс задач и планов реализации** (чтобы не объяснять агенту каждый раз):
  где живут задачи проекта (`gd-brain/tasks/studio/`, формат `STUDIO-NNN`,
  кросс-репо) и как завести карточку + написать **самодостаточный план
  реализации** — со ссылкой на канон `gd-brain/tasks/README.md` (разделы
  «Workflow» и «Планы реализации») и образцы (`gd-brain/tasks/studio/STUDIO-009`).
- **Польза:** ИИ (и владельцу как чек-лист). **Приоритет:** высокий.

## D4. Справочник модели документа

- **Артефакт:** `docs/reference/document-model.md`.
- **Зачем:** точная форма `document.json` и инварианты в одном месте.
- **Содержит:** поля (`schemaVersion`, `theme`, `motion`, `sections[]`); инвариант
  порядка (дробный index); связь с zod-схемой; примеры из
  [examples/](../../examples).
- **Польза:** оба. **Приоритет:** средний. **Триггер:** когда модель устаканится на
  Фазе 1.

## D5. Гайд «как добавить секцию-модуль»

- **Артефакт:** `docs/guides/authoring-blocks.md`.
- **Зачем:** воспроизводимый рецепт; одновременно — шаблон, по которому ИИ
  генерирует новые блоки правильно (а значит, меньше «доверия вслепую»).
- **Содержит:** контракт `BlockModule` (schema → render → preset → контролы)
  пошагово на примере `intro/envelope` и `hero`; требование «`defaults` и `render`
  делят один `P`» (см. IMP-001 в [backlog.md](backlog.md)).
- **Польза:** оба (для ИИ — особенно). **Приоритет:** средний.

## D6. Справочник конвейера render

- **Артефакт:** `docs/reference/render-pipeline.md`.
- **Зачем:** «как это работает» — отдельно от ADR-0002 «почему так решили».
- **Содержит:** `registry.get(type) → mod.render(props, ctx) → строка`; сборка
  `renderDocument` (HTML + CSS); почему в выводе нет React.
- **Польза:** оба. **Приоритет:** средний.

## D7. Архитектура редактора

- **Артефакт:** `docs/architecture-editor.md`.
- **Зачем:** зафиксировать устройство адаптера, когда он стабилизируется.
- **Содержит:** `BlockPreview`, изоляцию UI редактора через `editor-core`,
  anti-drift, «режим холста» для full-bleed секций.
  (`documentToPuck`/`puckToDocument` — неактуально после STUDIO-035).
- **Польза:** оба. **Приоритет:** низкий. **Триггер:** Фаза 1, после стабилизации
  `editor/`.

## D8. Диаграммы

- **Зачем:** визуальная опора онбордингу.
- **Польза:** тебе. **Приоритет:** низкий. **Триггер:** вместе с D1/D7.
