# Пресет линта «studio» для макетов Figma

Какие правила `figma-use lint` мы держим на макетах, какие сознательно
выключены и почему. Собран по итогам прогона на живом макете
(STUDIO-040, figma-use v0.13.5, 17 штатных правил).

Запуск:

```bash
make figma-lint PAGE="Sections"
```

Одна секция вместо страницы:

```bash
make figma-lint ARGS="--root 32:127"
```

## Почему список правил живёт в Makefile, а не в конфиге

`figma-use` читает `.figma-use.json`, и в типах конфига есть секция
`lint.rules` с пер-правило severity. **Она не работает**: CLI берёт из конфига
только `lint.preset`, а `rules` в движок не передаёт (`packages/cli/src/commands/lint.ts`
кладёт в `createLinter` лишь `preset` и `--rule`). Проверено прогоном — конфиг с
`"pixel-perfect": "off"` не меняет отчёт.

Отсюда два следствия для нас:

- состав пресета задаётся **явным списком `--rule`** (переменная
  `FIGMA_LINT_RULES` в [Makefile](../Makefile));
- **severity и опции правил не настраиваются**: работают зашитые дефолты
  (шкала отступов base 8, контраст AA, тач-цель 44 px, минимальный кегль 12 px).
  Поэтому «пресет» у нас — это состав, а не градация важности.

## Что включено (13 правил)

| Правило | Зачем в пресете |
| --- | --- |
| `no-hardcoded-colors` | Главное правило переноса: цвет без переменной = цвет без токена. На макете дало 60 → 0. |
| `text-style-required` | Текст без стиля — типографика, которую не выразить в теме. Дало 35 → 0. |
| `effect-style-required` | То же для теней: эффект без стиля не переносится в токены. |
| `consistent-radius` | Радиусы должны быть из шкалы — у studio она в `size.json` есть. |
| `touch-target-size` | Кнопка ниже 44 px в вёрстке станет непопадаемой; поймало три штуки. |
| `min-text-size` | Кегль < 12 px нечитаем на мобильном. |
| `no-default-names` | `Rectangle 1` не даёт MCP понять роль слоя — прямой ущерб переносу. |
| `no-hidden-layers` | Скрытые слои уезжают в экспорт как мусор. |
| `no-groups` | Группа вместо фрейма ломает auto layout и не имеет аналога в HTML. |
| `no-empty-frames` | Пустой фрейм — либо забытый слой, либо спейсер, который надо выразить отступом. |
| `no-deeply-nested` | Глубокая вложенность переносится в нечитаемую разметку. |
| `no-mixed-styles` | Смешанные шрифты внутри одного текста не переносятся в один тег. |
| `no-detached-instances` | Отвязанная копия компонента — потерянная переиспользуемость. |

Последние семь на текущем макете дают **ноль сообщений** — они держат
инварианты, а не создают шум. Весь пресет на макете STUDIO-040 даёт **1 info**
(тень `Фотокарточка` без effect style).

## Что исключено (4 правила)

| Правило | Почему выключено |
| --- | --- |
| `pixel-perfect` | Шум: 79 % всего «автофиксимого» объёма. Бессмысленно на повёрнутых узлах (грань всё равно ложится на сетку под углом) и **вредно** на честном центрировании нечётной ширины: `(393 − 280) / 2 = 56.5` — округление уводит элемент на полпикселя и ломает симметрию. |
| `color-contrast` | Ложные срабатывания на фото-фонах: правило поднимается по родителям до первого solid fill и не видит подложку. На макете даёт единственный error — «белое на белом» для текста поверх фотографии. |
| `prefer-auto-layout` | Замолкает на фрейме целиком, если хоть одна пара детей пересекается bounding-box'ами (`checkForOverlaps`), причём перекрытие считается по невращённому боксу. Чем декоративнее секция, тем вероятнее пропуск: на макете правило видело `Hero` (0 перекрытий) и молчало на `3 Schedule` (5 пар) и `5 RSVP` (7 пар). |
| `consistent-spacing` | Шкала зашита в линтер и не берётся из токенов проекта, а своей spacing-шкалы у studio пока нет (в `size.json` только `container`, `radius`, `section`). Пока её нет, советы вида «35 → 32» произвольны. **Вернуть в пресет, когда шкала появится в токенах.** |

## Чего пресет не проверяет

- **Auto layout как таковой.** Исключив `prefer-auto-layout`, мы не получаем
  замены: штатное правило смотрит только на флаг `layoutMode` контейнера.
  Контейнер, у которого auto layout включён, а все дети переведены в
  `ABSOLUTE`, проходит проверку и при этом не переживает ресайз. Нужное нам
  правило — «auto layout у каждого контейнера секции безусловно, absolute
  разрешён только слоям `deco/*`» — из коробки не существует и внешним плагином
  не подключается (движок грузит правила только из встроенного реестра).
- **Устойчивость композиции.** Критерий «ресайз родительского фрейма и
  удлинение текста не ломают вид» остаётся **ручным шагом** рецепта переноса.

## Ограничение, о котором надо помнить

Флаг `--fix` объявлен в CLI, но в теле команды не используется — это no-op.
Строка отчёта «Run with --fix to auto-fix N issues» вводит в заблуждение: она
считает вычисленные `FixAction`, которые никто не применяет. Проверено прогоном
на живом узле — координаты после `--fix` не изменились, и та же строка снова
появилась в отчёте. Любая правка макета делается вручную или адресным скриптом
через `figma-use eval`.
