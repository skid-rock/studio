# ADR-0008. Идентичность экземпляра секции в render-контракте

- **Статус:** принято
- **Дата:** 2026-08-24
- **Контекст задачи:** STUDIO-061 (RSVP-попап с якорем на экземпляр секции).

## Контекст

RSVP рендерит секцию и принадлежащий ей попап одной HTML-строкой. Чтобы два
экземпляра `rsvp` на странице не делили один якорь, id попапа должен выводиться
из `SectionNode.id`.

План STUDIO-061 предполагал, что достаточно передать
`{ ...node.props, id: node.id }` из `renderDocument`: холст уже подмешивает такой
же `id`. Проверка опровергла предположение:

- `defineBlock` прогоняет вход через `parseBySchema`, а тот намеренно отбрасывает
  ключи вне `ParamSchema` (`src/render-core/registry.ts`,
  `src/render-core/schema.ts`);
- холст перед вызовом реестрового `render` намеренно удаляет служебный `id`
  (`src/editor/render-block-html.ts`);
- схема RSVP по решению MVP содержит только `title`, `lead`, `submit`,
  `endpoint`, поэтому `id` до `rsvpModule.render` не доходит ни в экспорте, ни
  на холсте.

Статический экспорт подтвердил результат: секция документа с id `rsvp`
получила fallback-якорь `#rsvp-rsvp`. Два RSVP столкнутся.

## Предлагаемое решение

Идентичность экземпляра не должна становиться редактируемым prop схемы.
Предлагается передавать её через контекст:

```ts
interface RenderContext {
    doc: StudioDocument;
    sectionId: string;
}
```

`renderDocument` создаёт контекст для текущего узла, а edit-time мост холста
передаёт туда `node.id`. Модуль RSVP выводит якорь из `ctx.sectionId`.

Изменять `parseBySchema`, заводить скрытый параметр `id` в каждой схеме или
вводить тип `rsvp/popup` нельзя.

**Реализовано (2026-08-24, STUDIO-061):** поле добавлено в `RenderContext`
(`src/render-core/types.ts`), `renderDocument` собирает контекст на каждый узел
(`src/render-core/render.ts`), холст снимает служебный `id` с props и кладёт его
в контекст (`src/editor/render-block-html.ts`) — сигнатура `renderModuleHtml`
не изменилась, звонящие не тронуты. RSVP выводит якорь попапа из
`ctx.sectionId`. Поле **обязательное**: необязательное молча вернуло бы прежний
дефект, а компилятор его не ловит (`props` модулей расширяют
`Record<string, unknown>`, поэтому лишний ключ типизируется как `unknown`).

## Альтернативы

- **Разрешить служебный `id` поверх результата `parseBySchema`.** Меньше строк,
  но ломает правило «типизированный render получает только проверенные schema
  props» и создаёт неявный зарезервированный ключ.
- **Добавить `id` в схему RSVP.** Смешивает идентичность узла документа с
  редактируемыми данными секции и выставляет её в панель свойств.
- **Один константный id попапа.** Работает только для одного RSVP и нарушает
  контракт документа с повторяющимися типами секций.

## Последствия

- Это аддитивное изменение `RenderContext`, а не новое понятие оверлея или тип
  реестра.
- Потребуются согласованные правки экспорта и edit-time пути, поэтому исходная
  «одна строка для паритета id» недостаточна.
- Стабы `RenderContext` в тестах секций обязаны нести `sectionId` — при
  добавлении контракт потребовал правки 11 тестовых файлов.
- ADR-0002 дополнен: контекст render теперь несёт и идентичность узла.
