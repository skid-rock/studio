# Дизайн-система редактора studio

Единое место, где живут дизайн-решения интерфейса редактора (принципы, токены
хрома, роли компонентов). Правка дизайна = правка здесь → распространение в
код редактора (`src/editor/`).

**Статус: живой документ принципов.** Актуальный UI — живой редактор; HTML-мокапы
в [editor/](editor/) сейчас **песочница для экспериментов**, не обязательная
спека и не второй источник правды (спека STUDIO-030 выполнена).

**Решение на данный момент** (2026-07-18): мокапы не поддерживаем в синхроне с
кодом. В будущем они могут снова стать основой и основной точкой истины для UI —
тогда цикл «принципы → мокапы → код» вернём явно.

Выводы из референсов, на которых построены принципы, —
[references/README.md](references/README.md).

## Что такое дизайн-система (в двух словах)

Три уровня, каждый следующий собирается из предыдущего:

1. **Принципы** — словами: что считаем красивым/правильным. Ими решаются
   спорные случаи, для которых нет готового токена.
2. **Токены** — именованные константы дизайна (цвета, радиусы, тени, отступы).
   Аналогия из бэкенда: конфиг/контракт. Компоненты ссылаются на имена, никогда
   на значения. Поменял значение токена — изменение разъехалось по всему UI.
3. **Компоненты** — переиспользуемые блоки UI (кнопка, поле, карточка, панель),
   свёрстанные строго на токенах. Экраны собираются из компонентов.

Проверяемый инвариант (как правило границ в CLAUDE.md): **в вёрстке экранов нет
захардкоженных значений** — только `var(--chrome-*)` и `var(--color-*…)`.
Проверка greр-ом уже практикуется в STUDIO-030, сохраняем.

## Два контура токенов — не смешивать

| Контур | Что красит | Где живёт | Кто меняет |
| --- | --- | --- | --- |
| **Тема лендинга** (`--color-*`, `--font-*`, `--radius-*`) | Контент холста и экспортируемый HTML | `src/tokens/` (DTCG → Style Dictionary) | Пользователь редактора (пресеты, оверрайды) |
| **Хром редактора** (`--chrome-*`) | Панели, кнопки, поля — сам инструмент | Код: `src/editor/chrome.css`; черновик/песочница: `:root` в `docs/design/editor/editor.css` | Мы, через этот документ |

Хром **не зависит** от темы лендинга: пользователь переключил тему —
интерфейс редактора не «перекрасился». Тема живёт только внутри холста
(и в свотчах переключателя тем). Аналогия: домен (лендинг) и инфраструктура
(редактор) — разные слои, зависимость в одну сторону.

## Принципы

1. **Лендинг — главный герой.** Хром нейтральный, тихий, не конкурирует с
   холстом ни цветом, ни контрастом. Если элемент интерфейса заметнее контента —
   элемент неправ.
2. **Панели плавают.** Шапка, палитра, панель свойств — скруглённые карточки
   с воздухом от краёв окна, поверх фона-сцены. Не сплошные колонки.
3. **Глубина вместо границ.** Слои разводим светлотой и мягкой тенью, не
   бордерами. Фон-сцена глубже, панели ближе, попапы ещё ближе.
4. **Скругления по ролям:** панели — крупный радиус, контролы — средний,
   переключатели/индикаторы — pill.
5. **Один акцент.** Цвет только со смыслом: выделение/фокус/primary — один
   акцентный, опасное действие — терракота. Остальное — серые.
6. **Никаких значений мимо токенов.** Новый цвет/радиус/тень сначала становится
   токеном здесь, потом используется.

## Токены хрома (`--chrome-*`)

Значения калиброваны по референсам и мокапам STUDIO-030; дальше уточняются
в коде редактора (и при желании — в песочнице мокапов).

### Поверхности и текст

| Токен | Значение | Роль |
| --- | --- | --- |
| `--chrome-scene` | `#ececea` | Фон-сцена всего окна, «глубина» под панелями |
| `--chrome-scene-bg` | шум (SVG feTurbulence, ~4%) + radial-gradient сверху по центру | Слои поверх `--chrome-scene`: свет сверху + лёгкое зерно (решение №3) |
| `--chrome-panel` | `#ffffff` | Плавающие панели, шапка, попапы |
| `--chrome-hover` | `#f4f4f2` | Hover карточек и кнопок |
| `--chrome-border` | `#eaeae7` | Тонкие внутренние разделители (не контур панелей) |
| `--chrome-text` | `#1f2937` | Основной текст UI |
| `--chrome-muted` | `#6b7280` | Вторичный текст, подписи |
| `--chrome-accent` | `#1f2937` | Акцент хрома: primary-кнопка, фокус, выделение секции |
| `--chrome-on-accent` | `#ffffff` | Текст/иконки на акцентном фоне |
| `--chrome-scrim` | `rgba(31, 41, 55, 0.4)` | Затемнение под попапами |
| `--chrome-danger` | `var(--color-terracotta)` | Опасные действия (удалить) |

Примечание к `--chrome-accent`: как в референсе ref-01 (почти чёрный primary —
это и делает хром тихим). Акцент **фиксированный**, от темы лендинга не зависит
(решение №1); `--color-navy` в хроме больше не используется.

### Геометрия

| Токен | Значение | Роль |
| --- | --- | --- |
| `--chrome-radius-lg` | `16px` | Панели, попапы, крупные карточки |
| `--chrome-radius-md` | `10px` | Кнопки, поля, карточки блоков |
| `--chrome-radius-pill` | `999px` | Сегментированные переключатели, индикаторы |
| `--chrome-gap` | `12px` | Воздух: между панелями и краями окна, между панелями |
| `--chrome-pad` | `16px` | Внутренний отступ панелей |

### Тени (глубина)

| Токен | Значение | Роль |
| --- | --- | --- |
| `--chrome-shadow-panel` | `0 1px 2px rgba(0,0,0,.04), 0 8px 24px rgba(0,0,0,.06)` | Плавающие панели |
| `--chrome-shadow-pop` | `0 16px 48px rgba(0,0,0,.16)` | Попапы, тултипы, ghost при drag |

### Типографика хрома

Шрифт UI — Inter (`--font-body`), он уже среди шрифтов проекта.

| Роль | Размер/начертание |
| --- | --- |
| Текст UI, кнопки, поля | 13px / 400–500 |
| Подписи полей | 12px / 400 |
| Заголовки групп (uppercase) | 11px / 500, letter-spacing 0.08em |
| Заголовок панели | 14px / 500 |

Шрифты лендинга (`--font-display`, `--font-script`) в хроме **не используются** —
они принадлежат контенту.

## Компоненты

Историческая витрина — `docs/design/editor/components.html` (спека STUDIO-030;
сейчас песочница). Актуальная реализация компонентов — в `src/editor/`.

Базовый набор (по STUDIO-030):

- **Панель** (плавающая карточка) — новая базовая обёртка для шапки, палитры,
  панели свойств.
- **Кнопка**: обычная / иконка / primary / danger / disabled.
- **Виджеты полей** по типам `ParamSchema`: text, select, color, range.
- **Карточка блока** палитры (+ hover).
- **Обёртка секции** холста: обычная / hover / выделенная (+ мини-тулбар).
- **Drop-индикатор** и ghost для drag.
- **Попап** (оверрайды токенов).

## Процесс работы над дизайном

**Сейчас** (после STUDIO-032..035) изменения текут так:

```
принципы/токены (этот файл)
      → код редактора (src/editor/)
```

Мокапы в `docs/design/editor/` — опциональная песочница: можно править HTML/CSS
для экспериментов, синхронизировать с кодом не обязательно.

**Если мокапы снова станут точкой истины** — вернуть полный цикл:

```
принципы/токены (этот файл)
      → editor.css (:root --chrome-* и стили компонентов)
      → components.html (витрина — смотрим компонент в изоляции)
      → screen-*.html (экраны — смотрим композицию)
      → скриншоты shots/ (фиксация состояния)
      → код редактора
```

- Хотим изменить вид → сначала меняем токен/принцип здесь, затем правим CSS
  в коде (и при эксперименте — в песочнице). Если правка не выражается
  токенами — это новый токен или новый вариант компонента, а не локальный хак.
- Ограждение для песочницы (если правим мокапы): в `screen-*.html` нет
  инлайновых стилей со значениями цветов/радиусов/теней; в `editor.css`
  значения только в определениях `--chrome-*` и `@font-face`.
- `--chrome-*` уже в `src/editor/chrome.css`. Вариант с генерацией через Style
  Dictionary (как токены лендинга) — открытый вопрос, не блокер.

## Принятые решения (2026-07-04)

1. **Акцент хрома** — фиксированный тёмно-нейтральный `#1f2937`
   (`--chrome-accent`), не зависит от темы лендинга.
2. **Палитра блоков** — постоянная колонка-карточка. Компактный вариант
   (плавающий тулбар, как в референсах) отложен: блоков может стать много
   (возможно, за 100) — сначала посмотрим на реальный объём, потом придумаем
   компактность/поиск/группировку.
3. **Фон-сцена** — лёгкий градиент + шум (`--chrome-scene-bg`): radial-градиент
   со светом сверху по центру плюс едва заметное зерно feTurbulence (~4%) для
   глубины, как в ref-02.
